# 0.5.5 — 2026-09-11

### Fixed

- **The docked marker detail panel (tablet/desktop) could show a stale
  completion label after switching markers without closing it.** The panel
  keeps the same `MarkerDetailComponent` instance alive across marker
  switches (`@if (selectedMarker(); as sel)` stays true), only updating its
  `[marker]`/`[category]` `@Input`s — but `actionLabel`/`doneStatus` were
  wrapped in `computed()` despite reading only those plain `@Input` fields, no
  signal. With no signal dependency to invalidate them, Angular computed each
  once and cached it forever, so tapping a second completable marker without
  closing the panel kept showing the first marker's wording. Changed both to
  plain methods, which Angular re-evaluates on every check like the sibling
  `bonusStep()`/`bonusDone()` methods already did. The phone popover never hit
  this — a fresh popover, and so a fresh component instance, opens per tap.

### Changed

- Internal cleanup pass (raised by `fallow`): removed dead exports and an
  unused dependency, deduplicated the item-asset/map-tile cache services into
  a shared `WarmupCacheService` and the three data-prep scripts' Fan-API/
  write-if-changed helpers into `scripts/lib/`, and split the highest-
  complexity templates (Equipment's slot grid, Inventory's row, the
  onboarding wizard's step dots, the marker popover's completion controls)
  into smaller components. No behavior change beyond the fix above — build,
  lint, and the full test suite stay green throughout, and the three data-prep
  scripts produce byte-identical output.
